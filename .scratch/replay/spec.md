# Replay — 逐日回放與模擬交易

Status: ready-for-agent

## Problem Statement

使用者手上有一套能分析臺股歷史資料的工具，但它只能回答「這一年來這檔股票長什麼樣」。當使用者想練習判斷力時，這種呈現方式毫無用處——因為整張圖已經攤在眼前，右半邊的走勢在做決定的當下就看得到，任何「我當時應該會買」的自我評估都不可信。

使用者要的是把時間倒回過去某一天，讓行情一天一天長出來，在只看得到當下資訊的狀態下決定買賣，事後再檢討自己的決策。現有的 Backtest 功能無法滿足這件事：Backtest 是把一套機械式規則套用到整段歷史後給出報表，人不參與過程；使用者要參與的正是過程。

## Solution

新增 **Replay Session**：使用者任選一檔股票與一個起始日，開啟一條時間軸。畫面上 K 線、技術指標、籌碼只呈現 Cursor 當日及之前的資料；使用者按「下一日」推進，或讓它自動播放。

在任何一格，使用者可以送出買進或賣出的 Order，該 Order 於次一交易日以開盤價成交為 Fill，扣除真實的 Trading Cost。整段練習結束後，系統給出績效摘要，並與同期間的 Buy & Hold Baseline 對照，讓使用者知道自己的操作究竟創造了價值，還是只是搭上了順風車。

所有 Replay Session 與交易紀錄存進資料庫，可以續玩，也可以事後在終端機列出、檢視、匯出。

## User Stories

1. 作為一位想練習判斷力的投資人，我想要任選一檔股票開始回放，這樣我就能針對我真正在意的標的做練習。
2. 作為一位投資人，我想要任選一個起始日，這樣我就能重播我想研究的那一段特定行情。
3. 作為一位投資人，我想要在開始前就被告知資料涵蓋範圍不足，這樣我不會玩到一半才發現後面沒有資料。
4. 作為一位投資人，我想要在 Coverage 不足時直接看到該執行哪一行回補指令，這樣我不必自己猜要怎麼補資料。
5. 作為一位投資人，我想要 K 線圖只畫到 Cursor 當日，這樣我看不到未來，練習才有意義。
6. 作為一位投資人，我想要 Cursor 當日的 K 棒是完整的（開高低收皆可見），這樣它符合「收盤後看盤」的自然情境。
7. 作為一位投資人，我想要技術指標只用 Cursor 當日及之前的資料計算，這樣指標線不會洩漏未來走勢。
8. 作為一位投資人，我想要起始日之前的歷史資料被當作 Warm-up 載入，這樣一開場均線就是正確的，而不是從零慢慢長出來的假線。
9. 作為一位投資人，我想要在 Warm-up 資料不足以支撐某個指標時，該指標被明確標示為不可靠，這樣我不會誤信一條資料量不足的均線。
10. 作為一位投資人，我想要看到三大法人買賣超的籌碼面板，這樣我能把籌碼納入判斷。
11. 作為一位投資人，我想要在籌碼資料不存在的日期看到「無資料」而非 0，這樣我不會把資料缺口誤讀成法人沒有進出。
12. 作為一位投資人，我想要按「下一日」把 Cursor 推進一個交易日，這樣我能逐格觀察行情發展。
13. 作為一位投資人，我想要自動播放並可調整速度，這樣我能連續感受一段行情的節奏而不必一直點按鈕。
14. 作為一位投資人，我想要隨時暫停自動播放，這樣我能在關鍵位置停下來思考。
15. 作為一位投資人，我想要直接跳到某個指定日期，這樣我不必按幾十次才走到我想看的地方。
16. 作為一位投資人，我想要 Cursor 只走這檔股票自己有交易的日子，這樣停牌期間不會出現連按數次卻毫無變化的死當感。
17. 作為一位投資人，我想要在 Cursor 當日送出買進 Order，這樣我能表達「我現在想進場」的決策。
18. 作為一位投資人，我想要 Order 在次一交易日以開盤價成交，這樣我不會拿到我在決策當下不可能拿到的收盤價。
19. 作為一位投資人，我想要在同一格送出多筆 Order，這樣我能表達較複雜的當日決策。
20. 作為一位投資人，我想要以「張」為單位下單，這樣它符合我在真實券商下單的方式。
21. 作為一位投資人，我想要在建立 Session 時設定初始資金，這樣練習規模能貼近我真實的部位大小。
22. 作為一位投資人，我想要每筆 Fill 都扣除券商手續費與證券交易稅，這樣我的損益不會因為忽略成本而虛胖。
23. 作為一位投資人，我想要能設定券商手續費折數，這樣成本計算能貼近我實際的交易條件。
24. 作為一位投資人，我想要在次日開盤跳空導致現金不足時，該筆 Order 整筆作廢並被明確標記，這樣我事後檢討時看到的張數就是我當初的決策。
25. 作為一位投資人，我想要看到目前的 Position（股數與加權平均成本），這樣我隨時知道自己的持倉狀態。
26. 作為一位投資人，我想要看到目前的現金餘額與未實現損益，這樣我能評估當下的處境。
27. 作為一位投資人，我想要分批買進後看到加權平均成本，這樣它與我在真實券商對帳單上看到的數字一致。
28. 作為一位投資人，我想要賣出部分持股，這樣我能練習分批出場。
29. 作為一位投資人，我想要賣出時看到已實現損益，這樣我知道這一趟到底賺賠多少。
30. 作為一位投資人，我想要在按錯或想重來時把 Cursor 倒退到較早的日期，這樣我不必為了一個誤觸重開整個 Session。
31. 作為一位投資人，我想要 Rewind 時被明確告知該日之後的所有交易將被作廢，這樣我不會意外丟掉練習紀錄。
32. 作為一位投資人，我想要 Rewind 之後的帳戶狀態與交易紀錄完全一致，這樣不會出現「已退回三月卻持有五月成交部位」的矛盾。
33. 作為一位投資人，我想要能設定結束日，這樣我可以只練某一段特定期間而不必播到資料盡頭。
34. 作為一位投資人，我想要在到達結束日時自動停止並看到績效摘要，這樣練習有明確的收束點。
35. 作為一位投資人，我想要績效摘要包含總報酬、勝率與最大回撤，這樣我能量化自己的表現。
36. 作為一位投資人，我想要績效摘要與同期間 Buy & Hold Baseline 對照，這樣我能分辨自己是真的有能力，還是只是搭上了上漲趨勢。
37. 作為一位投資人，我想要 Replay Session 與交易紀錄被保存下來，這樣關掉瀏覽器不會讓半小時的練習蒸發。
38. 作為一位投資人，我想要重新開啟一個未完成的 Session 並從原本的 Cursor 繼續，這樣我能分次練完一段長行情。
39. 作為一位投資人，我想要對同一檔股票與同一起始日開啟多個 Session，這樣我能用不同做法練第二次、第三次。
40. 作為一位投資人，我想要替 Session 命名，這樣我事後認得出每一次練習的意圖。
41. 作為一位投資人，我想要在終端機列出所有 Session，這樣我能快速掃過自己練過哪些行情。
42. 作為一位投資人，我想要在終端機檢視單一 Session 的績效摘要，這樣我不必為了看一個數字開啟網頁介面。
43. 作為一位投資人，我想要把某個 Session 的交易明細匯出成 CSV，這樣我能在試算表裡做進一步分析與比較。
44. 作為一位投資人，我想要在 K 線圖上看到除權息日的標記，這樣持股跨過該日時帳面憑空少一段不會被我誤讀成崩盤。
45. 作為一位投資人，我想要 Replay 過程中完全不對外部 API 發出請求，這樣播放流暢，也不會踩到資料源的流量限制。
46. 作為一位投資人，我想要同一個 Session 重播兩次得到完全相同的資料，這樣我的練習紀錄是可重現、可信任的。
47. 作為一位投資人，我想要按需回補指定股票的多年歷史，這樣「任選起始日」不會被限縮在最近一年。

## Implementation Decisions

### 專案基礎

- V2 以複製既有 V1 程式碼為起點，Replay 是新增模組；不重寫既有的資料層、分析、圖表與 CLI。
- 第一步是驗證複製後的既有測試在新目錄下全數通過，再開始開發。

### Replay 服務層（新模組）

- 所有回放與模擬交易邏輯集中在一個**不依賴 Streamlit、不發出網路請求**的服務模組。
- 對外介面涵蓋：建立 Session、載入 Session、推進 Cursor、Rewind 至指定日、送出 Order、結算 Fill、取得 Cursor 當日的可見資料、產出績效摘要。
- Cursor 走的是**該股票自身**的交易日序列（由本地資料推導），不使用大盤交易日曆。
- Session 建立時檢查 Coverage；不足則拒絕建立並回報需要回補的範圍與指令，不做部分降級播放。
- Warm-up 策略：載入該股票起始日之前的**全部**本地資料。單股十年約 2,430 列，不值得為此做最佳化。當可用 Warm-up 長度小於某指標的 lookback 時，該指標標記為不可靠。
- 指標計算方式：對完整區間先計算，再依 Cursor 截斷。對滾動與遞迴指標而言，只要起算點相同，結果與逐格重算等價，但避免了自動播放時的重複運算。

### 模擬交易語意

- Order 於**次一交易日開盤價**成交（見 ADR 0001）。無限價單、無委託有效期——只有四個價位的日 K 無法支撐任何觸價判定。
- 一個 Session 綁定單一股票、只做多、以整張（1000 股）為單位。
- 現金不足時 Order 整筆作廢並標記原因，不自動減量、不允許負現金。
- Position 成本以**加權平均成本**計算，非 FIFO。
- Trading Cost 抽成獨立計算單元：買賣手續費各 0.1425%（最低 20 元、折數可設定、預設不打折）、賣出加徵證交稅 0.3%。不模擬滑價——沒有真實買賣盤，任何滑價數字都是憑空捏造的假精確。
- 此 Trading Cost 單元同時可補上既有 Backtest 模組完全沒有成本模型的缺口（該缺口導致現有回測績效偏高）。
- Rewind 將 Cursor 之後的所有 Order 與 Fill 一併刪除，帳戶狀態由剩餘交易重新推導，而非另存快照。

### 價格與資料

- 一律使用**原始成交價**，不做還原股價；除權息日在圖上標記（見 ADR 0002）。
- `adj_close` 欄位不得作為還原價使用——它目前 25 萬筆資料中無一與 `close` 不同。
- Replay 只讀本地資料庫，執行期間不呼叫任何外部 API。
- 歷史回補走既有的資料更新流程，按需針對少數股票回補（已驗證免費 FinMind token 可取得 2010 年日 K 與 2015 年三大法人資料）；不做全市場全歷史回補。

### 資料庫

- 新增兩張表：Replay Session（股票、起始日、結束日、當前 Cursor、初始資金、手續費折數、名稱、建立時間）與 Replay Order（所屬 Session、下單日、成交日、方向、張數、成交價、手續費、交易稅、作廢原因）。
- Position、現金與績效不落表，一律由 Order 紀錄推導，避免兩份真相不同步。
- 沿用既有 schema 建立與升級機制。

### 呈現層

- Streamlit 新增 Replay 頁面，薄到不含業務邏輯：呼叫服務層、畫圖、收集使用者輸入。
- 播放控制：下一日／上一日／自動播放（0.25~2 秒一格可調）／暫停／跳至指定日期，方向鍵可操作。
- 面板為價格＋技術指標＋籌碼三區。**不含基本面**——現有基本面資料只有單日快照且關鍵欄位為空，且缺少財報公告日，以報告期過濾必然造成 Lookahead。
- 圖表重用既有的 K 線繪圖模組，僅增加「截斷至 Cursor」的參數，不另寫繪圖程式。

### CLI

- 新增唯讀子命令：列出 Session、檢視單一 Session 摘要、匯出交易明細 CSV。
- CLI **不**提供互動式回放。

## Testing Decisions

好的測試只驗證外部可觀察的行為——送出什麼 Order、得到什麼 Fill、帳戶最後是什麼狀態——而不驗證內部如何組織。測試不應斷言私有函式的呼叫、內部資料結構的形狀，或指標在哪一層被截斷；那些是實作細節，會讓重構無故變紅。

**主要測試對象：Replay 服務層。** 這是唯一的新接縫，所有行為測試打這一層：

- Point-in-Time：Cursor 當日取得的資料不含任何未來日期的列。
- Warm-up：起始日之前的資料有被納入指標計算；長度不足時該指標被標為不可靠。
- Cursor 推進：只走該股票有資料的日期；到達結束日後停止。
- Fill 價格：Order 以次一交易日開盤價成交，而非當日收盤價。
- Trading Cost：手續費最低 20 元的下限、折數、賣出證交稅各自可獨立驗證。
- 資金不足：Order 整筆作廢並帶有原因，現金與 Position 不變。
- 加權平均成本：分批買進後的成本與部分賣出後的已實現損益。
- Rewind：截斷後的帳戶狀態等同於「從未下過那些單」。
- 持久化：存檔後重新載入，Cursor 與交易紀錄完全一致。
- 績效摘要：總報酬、勝率、最大回撤與 Buy & Hold Baseline 的計算。
- Coverage 不足時建立 Session 會被拒絕。
- 全程無網路呼叫。

**沿用既有接縫，不新增：** 資料庫隔離用既有的臨時 SQLite fixture 與 `set_default_db_path`；價格資料用既有的樣本資料 fixture 模式擴充（需要一組跨除權息、含停牌缺口、含跳空開盤的測試資料）。

**CLI 測試** 沿用既有的 `CliRunner` 模式，只驗證離開碼與輸出內容，不重複驗證服務層已測過的計算。

**Streamlit 頁面不建立測試接縫**，沿用既有對 app 模組的靜態 import 檢查。頁面若薄到需要測試才安心，代表邏輯放錯了層，應該往服務層搬。

**Prior art：** 既有的回測測試（同樣是「餵價格序列、斷言部位與績效」的形狀）、既有的 CLI 測試（`CliRunner` + 隔離 DB）、既有的 conftest fixtures。

## Out of Scope

- 分 K／Tick 回放。資料庫沒有盤中資料，免費資料源也不提供。
- 放空、融資融券、任何形式的槓桿。
- 限價單、停損單、委託有效期。
- 一個 Session 同時操作多檔股票的投資組合。
- 還原股價與股利資料源。
- 基本面面板。
- 策略自動逐日重播（把既有 Backtest 拆成可 step 的形式）。
- Replay 過程中即時抓取資料。
- 全市場全歷史資料回補。
- 修復既有的 `cache_metadata` 空表問題（獨立議題）。
- CLI 互動式回放。

## Further Notes

三個既有缺陷會被這個功能碰到，但都不是它造成的：

- `adj_close` 是假的還原價欄位，25 萬筆中無一與 `close` 不同。ADR 0002 已記錄不得使用。
- `cache_metadata` 表是空的，快取中繼機制形同未啟用。Replay 不依賴它（Coverage 直接查價格資料），但這個洞仍然存在。
- 既有 Backtest 沒有任何手續費與證交稅模型，現有回測績效偏高。本 spec 的 Trading Cost 單元可以順帶補上。

資料現況：日 K 涵蓋約一年（1,083 檔），三大法人僅約半年，兩者都短於實用的練習範圍，因此「按需回補」是第一次使用時的必要步驟，需在文件中明確說明。

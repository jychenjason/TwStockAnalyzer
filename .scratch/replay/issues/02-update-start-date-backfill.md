# 02 — 資料回補支援指定起始日

**What to build:** 使用者能把指定股票的日 K 與三大法人資料回補到數年前，而不是像現在這樣被硬編碼限制在最近 365 天。這是「任選起始時間」名副其實的前提——沒有這張票，回放只能玩最近一年。

**Blocked by:** None — can start immediately（與 01 平行，但需在 01 之後合併）。

**Status:** done

- [x] 資料更新指令接受起始日參數，未指定時維持現有的最近一年行為
- [x] 能將指定股票的日 K 回補至 2015 年並存入資料庫
- [x] 能將指定股票的三大法人資料回補至可取得的最早日期
- [x] 重複回補同一區間不產生重複資料
- [x] 回補進度與結果寫入既有的統一日誌格式
- [x] 資料源流量限制被尊重——大量回補時不會因超限而整批失敗，且失敗的股票被明確列出
- [x] 文件說明首次使用 Replay 前應如何回補資料
- [x] 測試以模擬資料源驗證起始日有正確傳遞、不實際呼叫外部 API

## Comments

- `update --start YYYY-MM-DD` 可回補日 K、籌碼與（新增的）除權息資料。
- 修掉一個會咬人的互動：既有的 incremental 邏輯只抓「最新一筆之後」的資料，若不特別處理，指定更早的起始日會被它默默略過。現在明確 --start 且早於快取起點時會繞過 incremental，實際抓回較早的區間。
- 有兩條測試（重複回補不產生重複列、單日失敗不中斷整批）沒有先紅：既有的 INSERT OR REPLACE 與 per-date try/except 本來就滿足。保留是為了守住行為，不宣稱它們驅動了實作。
- README 已補上回補說明與 600 req/hr 的限制警告。
